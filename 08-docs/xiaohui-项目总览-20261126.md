## 0. 一句话定位

一只 6 路舵机的 ESP32-S3 桌面机器狗：能语音对话（唤醒→识别→大模型→TTS）、查天气/新闻、放音乐、做动作、控灯珠、显示表情；配套一个 Web 控制台（设备管理 / 知识库 / 记忆 / 动作编排 / 固件 OTA）和一个云端大模型专区。

**当前水平**：是个「会说话、会摆姿势的音箱」，还不是「有情绪、会主动、能感知」的狗。缺什么见 §11。

## 3. 关键数据流

### 3.1 一次语音对话

```
设备唤醒(MultiNet 本地) → WS 连 8000 → hello(MCP) 
  → listen start → 持续推 opus 帧
  → 设备端 VAD 判停 → listen stop
  → 服务端 ASR 出文本(textHandle "detect"/"stop")
  → startToChat 分流：
       ① 关键词动作/灯 (try_handle_voice_command / _handle_hardware_cmd) → MCP 直连设备 → 固定短句
       ② 天气/新闻 (_handle_query_cmd) → 本地直查（带兜底）→ TTS 播
       ③ 知识库关键词 (_handle_kb_cmd) → 8077 /kb/search → TTS 播
       ④ 其他 → LLM 混合路由 → 专区 8013(/api/v1/chat) → DeepSeek
  → TTS(Edge 晓晓) 合成 → opus 帧 → 设备播放
  → 说完发 tts stop（+1.2s 补发一次）→ 设备回聆听
  → 本轮写入长期记忆（kb /memory/turn, source=voice）
```

### 3.2 一次动作（两条路径）

| 路径 | 触发 | 实现 |
|---|---|---|
| 关键词直通 | 识别文本命中动作词表 | `receiveAudioHandle._handle_hardware_cmd`：优先查控制台 `/api/hardware/actions` 的自定义姿态 → 走心跳 `pose` 指令；否则 `self.dog_action` |
| 大模型 function calling | 模型自己决定调 `self.dog_action` / `self.set_pose` | `device_mcp/mcp_executor.py`，执行成功直接回固定短句（不再二次问模型） |

### 3.3 设备 OTA / 配置下发

```
设备开机 → GET http://<你的服务器局域网IP>/ota/ (80→8080)
  → 控制台按请求 Host 生成 websocket.url（避免下发 127.0.0.1）
  → 返回 { server_time, websocket{url,token}, [activation], [firmware] }
设备心跳 400ms → POST /api/devices/heartbeat
  → 返回 { config: { agent{...}, wake_words[], commands[] } }
  → 固件据此：重建唤醒词命令表、执行动作/音量/pose 指令
```

### 3.4 长期记忆

```
语音每轮结束 → POST 8077 /memory/turn {user_id, user, assistant, source:"voice"}
  → turns 落库 → 规则抽取 facts（名字/年龄/住址/喜好/宠物/生日/"记住…"）
  → 槽位冲突消解（置信度高者取代，旧值进 fact_history）
连接建立 / 每轮后 1.5s → GET /memory/{user}/prompt
  → 拼进人设；走专区时通过 system_extra 透传（关键！）
控制台记忆页 → /api/agents/{id}/memory → facts + recent_turns（带来源标签）
```

## 4. 各组件详解

### 4.1 语音服务（`voice-server\main\xiaozhi-server`）

关键文件：

| 文件 | 作用 |
|---|---|
| `app.py` | 入口，加载 config、启动 WS/HTTP |
| `core/connection.py` | 每连接一个 ConnectionHandler：组件初始化、`chat()` 调 LLM、对话落库、长期记忆注入 |
| `core/handle/textHandle.py` | 处理设备消息：hello / listen(start/stop/detect) / abort / mcp / iot |
| `core/handle/receiveAudioHandle.py` | **核心**：音频帧入口、VAD、动作/灯/音乐/天气/新闻/知识库直通、卡死看门狗 |
| `core/handle/sendAudioHandle.py` | 发音频帧、tts start/stop、尾包补 stop |
| `core/handle/commandHandler.py` | 关键词兜底动作（`ACTION_REPLIES`） |
| `core/handle/reportHandle.py` | ASR/TTS 上报线程 |
| `core/providers/asr/fun_local.py` | FunASR SenseVoiceSmall 本地识别 |
| `core/providers/tts/edge.py` + `base.py` | Edge TTS 合成 + 文本切句 + 音频队列 |
| `core/providers/llm/openai/openai.py` | 混合路由：`_ask_zone()` 调专区，失败回退本地模型 |
| `core/providers/tools/device_mcp/` | 设备 MCP 工具调用（`call_mcp_tool`） |
| `core/api/console_handler.py` | 8003 HTTP：状态/动作/播报/点歌/编排 |
| `core/utils/memory_client.py` | 长期记忆写入 + 拉取（本轮新增） |
| `data/.config.yaml` | 服务端配置（ASR/VAD/LLM/TTS/wakeup_words） |
| `data/voice_settings.json` | 控制台「语音设置」的运行时覆盖（音色/语速/静音/人设/唤醒词） |
| `tmp/server.log` | 主日志（loguru 每日轮转） |

外部依赖：`.venv` 里已装 funasr/torch/edge-tts/opuslib_next；**opus.dll 在 `.venv\Scripts`，独立跑脚本时要加 PATH**。

### 4.2 控制台（`D:\AI-Companion-shared\xiaohui-ai\console`）

- FastAPI + SQLite（`data/console.db`），前端是 `static/index.html`（后台）与 `static/chat.html`（设备页/动作编排）。
- 主要模块：`app/main.py`（约 2700 行，路由都在这里）、`app/db.py`（store）、`app/auth.py`（登录，`CONSOLE_PASSWORD`）、`app/llm.py`（试聊，优先专区）。
- 数据库表：`agents` / `devices` / `logs` / `chat_messages` / `firmwares` / `users` / `device_commands` / `custom_actions` / `config_history`。
- 重要行为：
  - OTA 永远下发 websocket 地址（按请求 Host 生成），未绑定时发激活码
  - 心跳返回 `config.wake_words`（固定带「你好小慧」保底）与排队指令
  - 保存智能体配置时把 音色/模型/人设/唤醒词 同步到语音服务 `voice_settings.json`
  - 动作编排存 `data/action_sequences.json`

### 4.3 知识库（`kb-service`）

- 文档：`/kb/ingest`、`/kb/ingest_text`、`/kb/search`（向量 + BM25 混合）
- 长期记忆：`data/memory.db`
  - `facts`（当前有效事实，含 `source`）、`fact_history`（变更历史）、`turns`（原始轮次，含 `source`）
  - 抽取：正则规则为主；`LLM_CHAT_URL` 配了才走 LLM 抽取（**当前未配**）
  - 检索：`turns` 会进向量库，`/memory/search` 可用，但对话流程还没接（见 §11）

### 4.4 大模型专区（`D:\xiaohui-large-zone`）

- 入口 `run_zone.py`；`/health`（状态/模型/超时）、`/api/v1/chat`
- `app/services/fast_answers.py`：日期/星期/天气/新闻本地速答（命中直接返回 `model=fast-*`，不花 token）
- `app/services/tools.py`：function calling 工具（时间、天气、新闻）
- `app/services/deepseek_client.py`：DeepSeek 封装、工具循环（`model=deepseek-tools`）
- `.env`：`DEEPSEEK_API_KEY`、人设 `DOG_SYSTEM_PROMPT`、超时、默认城市
- `app/web/console.html`：专区自带调试页

### 几个反复出现的坑（值得背下来）

1. **设备「听不进去」**通常是服务端状态没清（`client_is_speaking` / `just_woken_up` / `client_abort`），不是设备坏了。
2. **设备「没声音」**可能是服务端在正式播报前插了一个 `tts stop`（看门狗抢跑），设备会转回聆听把音频丢掉。
3. **设备卡「说话中」**是最后一段没发 `tts stop`（原本有 `llm_finish_task` 前置条件，竞态下不发）。
4. **专区回答不带人设/记忆**：`_ask_zone` 只发用户那句话，必须用 `system_extra` 显式传。
5. **Open-Meteo 不可靠**（DNS 污染 + TLS 超时），天气必须有国内源兜底。
6. **PowerShell 脚本带中文路径必须存 UTF-8 BOM**，否则中文变乱码、路径都建错（备份脚本踩过）。
7. **控制台/知识库/专区不能提权到写目录就起不来**（SQLite WAL / 缓存）。
8. **`Get-NetTCPConnection` 在某些上下文静默返回空**，端口检测用 `netstat`。

## 9. 已知问题与限制

### 性能
- TTS（Edge 晓晓）是最大头，1.5~3s，且要新建连接；`合成 1 字 用时 2.0s` 说明是固定开销
- 专区对话**非流式**：故事类 LLM 10~14s，整段返回才开始合成
- 想再快：① 换流式云 TTS 或本地 Piper；② 专区改 SSE 流式 + TTS 边收边播

### 稳定
- 两个计划任务都要求用户登录；开机停在登录界面时不会启动
- 服务常由会话内启动 → 会话结束被回收，靠 KeepAlive 5 分钟内补回
- 舵机供电弱：做动作可能掉电重启

### 正确性
- 唤醒词自定义未生效（原因未定位，需串口日志）
- 编排只支持 4 路腿（`xhr0~3` 滑块），躯干/头部未接
- 编排动作没有语音触发（说「跳舞」走的是固件内置 dance）
- 记忆只做规则抽取，间接表达记不住；只有整体清空，没有逐条删除
- 语义召回（"上次说过什么"）向量已存但未接进对话
- 控制台 `llm.py` 的 `status()` 里 openai 分支不可达（前面 ollama 分支已 return）

### 硬件
- 无触摸/IMU/距离/视觉 → 对「被摸、被抱、有障碍」无感知（这是"像不像狗"的最大短板）

## 11. 路线图建议（按"像不像狗"排序）

| 优先级 | 事项 | 为什么 | 成本 |
|---|---|---|---|
| ★★★ | 触摸感知（铜箔/电容片贴头顶） | 「摸头有反应」是狗感最强的单项 | 几块钱 + 半天 |
| ★★★ | 情绪状态机 + 空闲自主行为 | 现在纯被动问答；有情绪/会主动才像活物 | 纯软件 1~2 天 |
| ★★★ | 长期记忆：逐条删除 + LLM 抽取 + 语义召回 | 记忆现在只是"登记表" | 1 天 |
| ★★☆ | TTS 换引擎 / 流式化 | 4~5s → 2s，体感差距最大 | 半天~2 天（看方案） |
| ★★☆ | IMU（MPU6050） | 被抱起/翻倒/晃动有反应 + 防摔 | 10 元 + 1 天 |
| ★★☆ | 动作编排 6 路 + 语音触发 | 现在只能 4 路、只能网页点 | 半天 |
| ★☆☆ | 唤醒词自定义（WakeNet 定制或调阈值重烧） | 用户明确想要 | 需乐鑫定制流程 |
| ★☆☆ | 距离/视觉（ToF / 摄像头） | 避障、跟随、认人 | 较高 |
| ★☆☆ | 情绪与语音/表情同步（口型、打断体验） | 细腻度 | 1 天 |
